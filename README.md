# AES-128 Encryption Core (Iterative)

AES-128 encryption in Verilog. One round of logic is reused for 10 clocks,
and the round keys are generated on the fly, so only one 128-bit key
register is needed. The interface is valid/ready: key and plaintext in,
ciphertext out. Encryption only.

## Features
- SubBytes, ShiftRows, MixColumns and AddRoundKey as separate, individually
  tested modules
- S-box generated by a Python script from its GF(2^8) definition (inverse
  plus affine transform), not typed by hand
- On-the-fly key expansion: one round key per clock, no stored key schedule
- valid/ready input handshake; `out_valid` pulses for one cycle, and
  `ciphertext` stays stable until the next block is accepted
- Inputs presented while the core is busy are ignored (tested)
- Lint-clean under Verilator `-Wall`

## Performance
| Metric | Value |
|---|---|
| Latency (accept edge to `out_valid`) | 10 clock cycles |
| Back-to-back throughput | 1 block per 11 cycles |

Measured in simulation. The 10 cycles are the 10 rounds; the initial
AddRoundKey happens on the accept edge.

## Run it
Requires Icarus Verilog and Verilator (`sudo apt install iverilog verilator`),
Python 3 and `pycryptodome` (`pip install pycryptodome`, a virtual
environment is recommended).

    make sim_sbox      # S-box vs FIPS-197 table values
    make sim_round     # ShiftRows and MixColumns vs FIPS-197 Appendix B
    make sim_aesround  # SubBytes and full rounds 1-3, final round (Appendix B)
    make sim_keyexp    # key expansion vs FIPS-197 Appendices A and C.1
    make sim_top       # full core vs pycryptodome, 504 blocks
    make lint          # Verilator lint of every module
    make synth         # Yosys synthesis statistics
    make clean

`rtl/aes_sbox.v` is generated by `scripts/gen_sbox.py` (run by the make
targets) and is committed so the design can be simulated without Python.

## Verification
Each stage is checked against an independent source before the next one is
built.

| Test | Reference | Result |
|---|---|---|
| S-box | 6 entries from the FIPS-197 table, all 256 outputs, permutation check | PASS |
| ShiftRows, MixColumns | FIPS-197 Appendix B round 1, published single-column examples | PASS |
| SubBytes, rounds 1-3, final round | FIPS-197 Appendix B | PASS |
| Key expansion | All 10 round keys of Appendix A, rounds 1, 2, 9, 10 of Appendix C.1 | PASS |
| Full core (`make sim_top`) | `pycryptodome`: the two FIPS-197 examples, all-zero and all-one inputs, 500 random key/block pairs | 504 checked, 0 errors |

The vector generator asserts that its reference reproduces the published
FIPS-197 ciphertexts before writing any vectors. In the full-core test, every
second block also drives garbage onto the inputs while the core is busy, to
confirm they are ignored, and the testbench checks that every block has the
same 10-cycle latency.

## Synthesis (Yosys, generic gate library)

| Metric | Value |
|---|---|
| Flip-flops | 262 |
| Logic cells | 10,707 |
| Total cells | 10,969 |
| Latches | 0 |

The flops are 128 state + 128 round key + 4 round counter + busy + out_valid.
The count is dominated by MUX cells (7,307), which is how generic synthesis
maps the case-statement S-box tables. Reproduce with `make synth`.

## Limitations
- Encryption only: no decryption, no modes of operation (ECB-style
  single-block interface only).
- Functional RTL only. No side-channel countermeasures and no
  constant-time guarantees. Not for protecting real data.
- The S-box is a lookup table, which is simple but large. A composite-field
  S-box would use much less area.
- Generic gate counts with no timing. One round per clock puts the S-boxes,
  MixColumns and the key schedule in one combinational path, so the achievable
  clock frequency is not yet known.
- Verified against FIPS-197 examples and 500 random blocks, not the full NIST
  known-answer test suite. Not tested with formal methods.
